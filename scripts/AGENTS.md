# scripts

## Purpose

Offline data pipeline and the runnable oracles behind `GATES.md`.

## Ownership

- `crawl.ts` — discovery + README enrichment into `data/raw.json`
- `build-snapshot.ts` — `data/raw.json` → `data/snapshot.json`
- `sync-public.ts` — writes `public/data/index.json` from the snapshot before
  dev/build; the browser copy keeps only `schemaVersion`, `updatedAt`, `totals`,
  `origins`, `recipes` and `families`
- `prune-rsc-payloads.ts` — after `next build`, deletes the four `.txt` RSC
  payloads the App Router writes per route (21,468 files, 254 MB of the
  unpruned export). What ships is about 5,400 files and 169 MB. Safe only
  because every internal link is a plain anchor. Keeps `llms.txt` and
  `robots.txt`, which share the extension, and exits non-zero if either is
  missing. Runs as the last step of `npm run build`.
- `build-og.ts` — copies the card generated by `app/og/route.tsx` in `out/` to
  `out/og.png` and `public/og.png`, then removes the extensionless original so a
  static host never serves it as `application/octet-stream`.
- `build-llms-txt.ts` — writes `public/llms.txt` from the snapshot. Generated,
  never hand-edited: a written file would keep describing a snapshot the site
  has already moved past. Placeholders are `{UPPER_SNAKE}` and must all resolve;
  the code reads `snapshot.totals.*`, not the top level.
- `build-readme-counts.ts` — rewrites the README's `<!-- counts:begin -->` block
  from the snapshot, so the index size the README states cannot drift from the
  data. `--check` exits non-zero when the block is stale; `verify/dox.mjs` runs
  it, so a hand-edited number fails the gate instead of rotting.
- `lib/hf.ts` — Hub REST client (pagination, retries, timeouts, expansions) and
  `checkLink` (Hub API `GET /api/models/<id>`, 10s timeout, bounded retries) for
  `ok`/`gated`/`dead` status without downloading HTML pages.
- `lib/incremental.ts` — sha + `PARSER_VERSION` keyed cache decision (unit-tested)
- `lib/pool.ts` — bounded concurrency
- `verify/*.mjs` — gate oracles: `static`, `suite`, `snapshot`, `app-smoke`,
  `seo`, `automation`, `dox`, `links`, sharing helpers in `verify/util.mjs`
- `verify/links.mjs` — G-links: checks every Hugging Face link target referenced
  by the committed snapshot via the Hub API. Fails on dead artifact repos (404),
  warns on dead origins and gated repos. Runs only in `refresh.yml`, never in
  `npm test` (the suite must stay offline). Uses bounded concurrency (20) and
  short timeouts; semantics must stay `ok`/`gated`/`dead`.
- `verify/security.mjs` — G11: actions pinned to SHAs, `pull_request_target`
  confined to `dependabot-auto-merge.yml` and then only without
  `actions/checkout` and gated to `dependabot[bot]`, `ci.yml` still running the
  pages actions (the precondition for auto-merging action majors), dependabot
  configured, CSP present, no `next/link` in source, no tracked secrets, shipped
  deps free of high advisories.
- `../.github/dependabot.yml` — weekly npm + actions updates, grouped so a
  week is one review rather than twenty. Groups are `minor`/`patch` only, so a
  single major cannot poison a whole group into `semver-major`.
- `../.github/workflows/ci.yml` — the full gate suite on every pull request,
  plus `pages-dry-run`, which builds the export and runs
  `configure-pages` / `upload-pages-artifact` without deploying. That job is
  what makes an action bump provable before it merges. Caches `.next/cache` to
  speed repeated builds without changing output.
- `../.github/workflows/dependabot-auto-merge.yml` — merges npm patch, dev
  minor, and any `github_actions` bump once CI passes; npm minor on a
  production dependency and every npm major stay for a human. Uses
  `pull_request_target`, because Dependabot's `pull_request` runs get a
  read-only token whatever `permissions:` declares. Never add a checkout here.
  Merging a PR that edits `.github/workflows/` needs the `workflows` scope,
  which `GITHUB_TOKEN` cannot hold, so it uses the optional `AUTOMERGE_TOKEN`
  PAT when present and otherwise skips with an explanation.
- `../.github/workflows/refresh.yml` — the only path that publishes. Daily
  03:17 UTC, on demand, and on any push to `main` touching the pipeline. It
  crawls, rebuilds the snapshot, runs the gates, checks HF links, builds,
  prunes, uploads `out/` to Pages, commits the new snapshot, deploys, checks
  the live site is fresh, and opens or closes the `refresh-failure` issue.
  Caches `data/cache` and `.next/cache`; `app-smoke` runs with
  `SMOKE_SKIP_BUILD=1` after the build step to avoid a duplicate export.
  `concurrency: refresh-index` with `cancel-in-progress: false` keeps two
  refreshes from racing; a human push can still land mid-run, which the commit
  step reports rather than fails.
- `verify/seo.mjs` also asserts the social card and icons resolve to real files
  with no query string, and that no Next.js template asset is still shipping. A
  broken `og:image` 404s only in someone else's preview, so nothing else catches it.
- `verify/snapshot.mjs` also compares coverage against the committed snapshot and
  refuses a refresh that loses more than 4%. Without it a crawl that hits HTTP
  429 quietly publishes a smaller index while every absolute floor still passes.
  It also re-derives each recipe's numbers from the repo it cites as evidence,
  so a `/repo/` page can never quote a card that says something else.

## Local Contracts

- Discovery is two passes (`filter=heretic`, then `search=heretic`) with the
  tagged pass winning collisions (p-e-w/heretic#450). Do not add a third pass
  without a proven recall gain.
- Every network request has a timeout and bounded retries; one failing repo must
  never abort a crawl. A retry loop that runs out of attempts must throw the real
  cause (`HF 429 for …`), not a generic "failed to fetch", and must not sleep
  again on the last attempt.
- The crawler writes atomically (`.tmp` + rename) and is resumable via
  `data/cache/cards/*.json`.
- `data/raw.json` is an intermediate and is gitignored; only
  `data/snapshot.json` is published. A fresh clone therefore needs
  `npm run refresh` before `npm run snapshot` can succeed.
- `HF_TOKEN` is **required in CI**, not merely helpful. Anonymous crawls are
  rate-limited and every repo whose README returns 429 is dropped. It should be
  a fine-grained read-only token; `npm run crawl` warns when it is absent.
- Verification scripts print a success-only marker and exit non-zero on failure.

## Work Guidance

- Test cache/classification behaviour in `tests/` rather than shell scripts.
- Keep the crawl polite: concurrency defaults to 15 and `--concurrency` exists to
  lower or raise it; no authenticated scraping of HTML, only the Hub API. Link
  checks use the Hub API with bounded concurrency/timeouts and must preserve
  `ok`/`gated`/`dead` semantics and dead-artifact failure policy.
- Progress counters report completed work, not input positions, because workers
  finish out of order. Never commit `data/cache/` or crawl logs.

## Troubleshooting

What breaks, how to tell, and the repair. Most of it is one of five causes.

- **An open `refresh-failure` issue means the site is stale right now.** The
  issue carries the run URL. Fix forward; the next green run closes it. Do not
  close it by hand, or a live outage starts to look resolved.
- **`verify-freshness` red while `deploy` is green.** The export published, but
  `https://hdir.sdad.pro/data/index.json` still serves the previous snapshot.
  Usually Pages cache lag, which the job retries four times. If it keeps
  failing, the deploy aliased nothing and the host is frozen.
- **`snapshot` red with a coverage drop.** A crawl lost repos, almost always
  HTTP 429 on the unauthenticated path. Check `HF_TOKEN` first. Never lower the
  4% floor to get green: that floor is the alarm, not the fault.
- **Every README fetch 401, or the index silently shrinks.** Expired
  `HF_TOKEN`. The preflight exists so this fails with that reason instead of
  reading as "this repo has no card".
- **A dependency PR opens and nothing merges.** Read the `auto-merge` job log;
  it prints the decision as `Allowed to auto-merge: no (ecosystem=… update=…
  dependency=…)`. `no` is policy, not a failure.
- **`auto-merge` green but the PR still open.** Either the PR edits
  `.github/workflows/` while `AUTOMERGE_TOKEN` is missing or expired, or CI did
  not pass. The step prints which of the two.
- **A merge landed but the site did not change.** Pushes made with
  `GITHUB_TOKEN` do not trigger workflows (GitHub's recursion guard), so
  `refresh.yml` never ran. The next 03:17 UTC cron deploys it. A human push
  does trigger it.
- **Action bumps stop merging roughly a year from setup.** The
  `AUTOMERGE_TOKEN` PAT expired. Mint a fine-grained one (contents,
  pull-requests, workflows = write, this repo only) and replace the secret.
- **`security.mjs` complains about `pages-dry-run`.** The pages actions were
  removed from `ci.yml`. Auto-merging action bumps is only sound while that job
  runs them; restore the job, do not relax the gate.
- **`npm audit` reports `minimatch`.** Expected. ESLint pins `minimatch ^10`
  while the advisory's fix is 11+, so no supported resolution exists. Dev-only,
  and the patterns come from our own `eslint.config`, so it is not reachable.
  Do not "fix" it by downgrading ESLint or forcing an override outside ESLint's
  declared range.
